# Bookmarks Plus 1.5.0 Pre-release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare, publish, and verify Bookmarks Plus `1.5.0` as the next VS Code Marketplace pre-release.

**Architecture:** The preparation PR changes only extension release metadata and the changelog, then proves the existing extension, bundled MCP server, and packaged native MCP integration still pass their release gates. After that PR merges, a separately confirmed `v1.5.0` tag push invokes the existing immutable-commit Publish workflow; publication is verified before Issue #159 and milestone `v1.5.0` close.

**Tech Stack:** npm; VS Code extension packaging; GitHub Actions; VS Code Marketplace; Node.js 20 release lane.

**Spec:** Issue #159

## Global Constraints

- Use `1.5.0`, whose odd minor selects the pre-release channel (`docs/release-strategy.md:L61-L84`; Issue #159).
- Keep the standalone MCP package at `0.1.0`; it has independent SemVer and a separate `mcp-vX.Y.Z` lane (`docs/release-strategy.md:L3-L36`; Issue #159).
- The preparation PR must reference Issue #159 without closing it; closure happens only after Marketplace and GitHub pre-release verification (Issue #159).
- Do not push `v1.5.0` until the preparation PR is merged and the user explicitly confirms publication (`docs/release-strategy.md:L262-L282`).
- Make no runtime behavior changes. This metadata/documentation-only release preparation adds no new production test; existing release contract tests and package gates provide verification (Issue #159).

## Review Focus

- `package.json` and the root `package-lock.json` must both report `1.5.0`; verify both after using npm's version command.
- The odd-minor guard must accept `1.5.0` for `prerelease` and reject it for `stable`; run both CLI paths.
- The changelog extractor must return the complete `1.5.0` section and must not include the next empty `Unreleased` section.
- The generated VSIX must retain the bundled native MCP server and pass the packaged integration test on the prepared version.
- The published workflow must resolve the immutable `v1.5.0` commit and create a Marketplace pre-release plus matching GitHub pre-release.
